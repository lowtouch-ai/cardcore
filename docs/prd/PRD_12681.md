# Product requirements document: account and customer management

## Purpose and scope

This document defines the account and customer management behavior found in the CardCore legacy application. It covers regular user access to account inquiry, account and customer update, card list, card detail, card update, bill payment, batch account balance changes, statement generation, migration import/export, and the optional account inquiry over MQ. Source code: [screens-and-transactions.md](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/docs/screens-and-transactions.md), [batch-jobs.md](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/docs/batch-jobs.md), [data-model.md](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/docs/data-model.md), [optional-modules.md](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/docs/optional-modules.md).

The base repository is legacy source only. The application does not build or run locally; execution and verification happen through CICS transactions and batch jobs on a mainframe or compatible emulator. Source code: [AGENTS.md](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/AGENTS.md).

The account and customer management scope does not include a standalone customer add, customer delete, or customer list screen in the base online application. Customer maintenance appears only as part of the account update screen. Source code: [COACTUPC.cbl](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/app/cbl/COACTUPC.cbl), [COACTVWC.cbl](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/app/cbl/COACTVWC.cbl), [screens-and-transactions.md](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/docs/screens-and-transactions.md).

## Users and permissions

The application signs users in through a user-security record, compares the submitted password, stores the signed-in user and user type in session context, and routes users to either the administrative menu or the regular menu. Source code: [COSGN00C.cbl](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/app/cbl/COSGN00C.cbl), [CSUSR01Y.cpy](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/app/cpy/CSUSR01Y.cpy), [COCOM01Y.cpy](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/app/cpy/COCOM01Y.cpy).

Administrators are routed to a menu for user-security maintenance and optional transaction-type setup. The administrative menu does not expose account inquiry, account update, card maintenance, or bill payment as administrative functions. Source code: [COADM01C.cbl](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/app/cbl/COADM01C.cbl), [COADM02Y.cpy](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/app/cpy/COADM02Y.cpy).

Regular users can access account view, account update, card list, card detail, card update, and bill payment from the regular menu. The regular menu checks whether the chosen option is allowed for the current user type and reports a clear message when a selected optional function is not installed. Source code: [COMEN01C.cbl](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/app/cbl/COMEN01C.cbl), [COMEN02Y.cpy](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/app/cpy/COMEN02Y.cpy).

The account and card programs rely on the sign-on and menu flow for access control. No additional per-screen role check was found inside the account view, account update, card list, card detail, card update, or bill payment programs. Source code: [COACTVWC.cbl](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/app/cbl/COACTVWC.cbl), [COACTUPC.cbl](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/app/cbl/COACTUPC.cbl), [COCRDLIC.cbl](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/app/cbl/COCRDLIC.cbl), [COCRDSLC.cbl](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/app/cbl/COCRDSLC.cbl), [COCRDUPC.cbl](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/app/cbl/COCRDUPC.cbl), [COBIL00C.cbl](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/app/cbl/COBIL00C.cbl).

## Data model overview

A customer record represents the person associated with one or more cards or accounts. It stores identity, contact, address, government identity, date of birth, EFT account, primary-cardholder status, and credit score information. Source code: [CVCUS01Y.cpy](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/app/cpy/CVCUS01Y.cpy), [data-model.md](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/docs/data-model.md).

An account record represents the financial account. It stores account status, current balance, credit and cash limits, open and expiration dates, reissue date, current-cycle credit and debit totals, billing ZIP, and account group. Source code: [CVACT01Y.cpy](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/app/cpy/CVACT01Y.cpy), [data-model.md](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/docs/data-model.md).

A card record represents a credit card attached to an account. It stores the card number, account relationship, security code, embossed cardholder name, expiration date, and active status. Source code: [CVACT02Y.cpy](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/app/cpy/CVACT02Y.cpy), [data-model.md](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/docs/data-model.md).

A card cross-reference record links customer, account, and card together. Account-based alternate indexes allow the application to find a customer and card relationship from an account number. Source code: [CVACT03Y.cpy](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/app/cpy/CVACT03Y.cpy), [XREFFILE.jcl](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/app/jcl/XREFFILE.jcl), [data-model.md](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/docs/data-model.md).

Transactions are financial activity records tied to cards and accounts. Posting, bill payment, interest calculation, and statement generation all use transaction records to update balances or present account activity. Source code: [CVTRA05Y.cpy](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/app/cpy/CVTRA05Y.cpy), [CBTRN02C.cbl](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/app/cbl/CBTRN02C.cbl), [COBIL00C.cbl](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/app/cbl/COBIL00C.cbl), [CBACT04C.cbl](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/app/cbl/CBACT04C.cbl), [CBSTM03A.CBL](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/app/cbl/CBSTM03A.CBL).

## Account and customer inquiry

### Description

A regular user can look up an account and view the linked customer information on a single account inquiry screen. The user supplies an account number, and the system retrieves the linked account and customer records for display. Source code: [COACTVWC.cbl](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/app/cbl/COACTVWC.cbl), [COACTVW.bms](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/app/bms/COACTVW.bms), [screens-and-transactions.md](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/docs/screens-and-transactions.md).

The screen presents account status, balances, limits, account dates, account group, customer identity, address, phones, government identity, EFT account, date of birth, primary-cardholder status, and credit score information. Source code: [COACTVWC.cbl](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/app/cbl/COACTVWC.cbl), [COACTVW.bms](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/app/bms/COACTVW.bms).

### Business rules and logic

The account number must be supplied as a valid nonzero account number. If the input is blank, nonnumeric, or zero, the system keeps the user on the screen and displays an input error message. Source code: [COACTVWC.cbl](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/app/cbl/COACTVWC.cbl).

The system first uses the account number to find the account-to-customer relationship, then reads the account record, then reads the customer record. If any of these records is missing or the file read fails, the system displays an error and does not show a completed inquiry result. Source code: [COACTVWC.cbl](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/app/cbl/COACTVWC.cbl).

### Roles and permissions

This use case is available from the regular user menu. No separate role check was found inside the account inquiry program. Source code: [COMEN02Y.cpy](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/app/cpy/COMEN02Y.cpy), [COMEN01C.cbl](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/app/cbl/COMEN01C.cbl), [COACTVWC.cbl](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/app/cbl/COACTVWC.cbl).

### Key data involved

This use case reads account, customer, and card cross-reference data. It does not write account or customer data. Source code: [COACTVWC.cbl](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/app/cbl/COACTVWC.cbl), [CVACT01Y.cpy](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/app/cpy/CVACT01Y.cpy), [CVCUS01Y.cpy](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/app/cpy/CVCUS01Y.cpy), [CVACT03Y.cpy](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/app/cpy/CVACT03Y.cpy).

### Notable constraints

Customer identity and financial profile details are visible to regular users through this screen. The code formats and displays sensitive identity values rather than masking the entire value. Source code: [COACTVWC.cbl](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/app/cbl/COACTVWC.cbl), [COACTVW.bms](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/app/bms/COACTVW.bms).

## Account and customer update

### Description

A regular user can retrieve an account and update account and customer details on the same screen. The screen is account-led: the user searches by account number, the system loads the linked customer, and the user edits account and customer fields together. Source code: [COACTUPC.cbl](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/app/cbl/COACTUPC.cbl), [COACTUP.bms](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/app/bms/COACTUP.bms), [screens-and-transactions.md](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/docs/screens-and-transactions.md).

The user must confirm a valid change before the system saves it. A validated change is not written until the user confirms with the designated save key. Source code: [COACTUPC.cbl](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/app/cbl/COACTUPC.cbl).

### Business rules and logic

The account search input must be present, numeric, nonzero, and the expected account length. Invalid account input produces a screen message and blocks the search or update. Source code: [COACTUPC.cbl](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/app/cbl/COACTUPC.cbl).

The system compares the edited account and customer values with the originally loaded values. If nothing changed, the system reports that no change was detected and does not write to the files. Source code: [COACTUPC.cbl](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/app/cbl/COACTUPC.cbl).

Account status and primary-cardholder indicators must be answered as yes or no values. Source code: [COACTUPC.cbl](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/app/cbl/COACTUPC.cbl).

Money fields must be valid signed numeric amounts. This applies to account balance, credit limit, cash limit, and current-cycle credit and debit amounts. Source code: [COACTUPC.cbl](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/app/cbl/COACTUPC.cbl).

Dates are checked by the shared date validation routine. The routine checks valid year, month, day, leap-year behavior, and rejects future dates for date-of-birth validation. Source code: [COACTUPC.cbl](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/app/cbl/COACTUPC.cbl), [CSUTLDPY.cpy](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/app/cpy/CSUTLDPY.cpy), [CSUTLDWY.cpy](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/app/cpy/CSUTLDWY.cpy).

Credit score must be numeric and must fall within the accepted score range. Source code: [COACTUPC.cbl](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/app/cbl/COACTUPC.cbl).

Required name and location fields must be alphabetic where the screen expects words rather than numbers. First name, last name, city, state, and country are required. Middle name is optional. Source code: [COACTUPC.cbl](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/app/cbl/COACTUPC.cbl).

Primary address line is required. Secondary address line is accepted as optional. Source code: [COACTUPC.cbl](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/app/cbl/COACTUPC.cbl).

State and ZIP code are validated together against a lookup table. The system checks that the state is recognized and that the ZIP code prefix is valid for that state. Source code: [COACTUPC.cbl](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/app/cbl/COACTUPC.cbl), [CSLKPCDY.cpy](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/app/cpy/CSLKPCDY.cpy).

Phone numbers are optional only when left fully blank. If the user enters part of a phone number, the system requires the full phone number and validates its parts. Source code: [COACTUPC.cbl](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/app/cbl/COACTUPC.cbl), [CSLKPCDY.cpy](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/app/cpy/CSLKPCDY.cpy).

Social Security number must be complete, numeric, nonzero, and must not use disallowed leading values. Source code: [COACTUPC.cbl](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/app/cbl/COACTUPC.cbl).

The EFT account value is required and must be numeric and nonzero. Source code: [COACTUPC.cbl](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/app/cbl/COACTUPC.cbl).

The government identity value is accepted and written, but no specific validation rule was found for it. Source code: [COACTUPC.cbl](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/app/cbl/COACTUPC.cbl).

### Roles and permissions

This use case is available from the regular user menu. No separate role check was found inside the account update program. Source code: [COMEN02Y.cpy](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/app/cpy/COMEN02Y.cpy), [COMEN01C.cbl](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/app/cbl/COMEN01C.cbl), [COACTUPC.cbl](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/app/cbl/COACTUPC.cbl).

### Key data involved

This use case reads card cross-reference data to locate the linked customer and account. It writes the account record and the customer record. Source code: [COACTUPC.cbl](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/app/cbl/COACTUPC.cbl), [CVACT01Y.cpy](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/app/cpy/CVACT01Y.cpy), [CVCUS01Y.cpy](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/app/cpy/CVCUS01Y.cpy), [CVACT03Y.cpy](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/app/cpy/CVACT03Y.cpy).

### Notable constraints

The update flow uses a display, validate, confirm, lock, compare, and save pattern. Before saving, the system re-reads the current account and customer records for update and compares them with the records that were originally displayed. If another process changed the data first, the user is told that the record changed and the save is blocked. Source code: [COACTUPC.cbl](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/app/cbl/COACTUPC.cbl).

The system rewrites the account first and then the customer. If the customer rewrite fails after the account rewrite, the program issues a rollback. Source code: [COACTUPC.cbl](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/app/cbl/COACTUPC.cbl).

## Card list

### Description

A regular user can list cards, optionally filtered by account number and card number. The list supports paging and allows one selected card to be opened for detail or update. Source code: [COCRDLIC.cbl](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/app/cbl/COCRDLIC.cbl), [COCRDLI.bms](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/app/bms/COCRDLI.bms), [screens-and-transactions.md](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/docs/screens-and-transactions.md).

### Business rules and logic

Blank filters are allowed. When the user enters an account or card filter, the value must be numeric. Source code: [COCRDLIC.cbl](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/app/cbl/COCRDLIC.cbl).

The screen shows a fixed number of card rows per page and supports forward and backward paging. Source code: [COCRDLIC.cbl](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/app/cbl/COCRDLIC.cbl).

The user may select only one row action at a time. The action must be either view detail or update. Invalid actions or multiple selected rows produce an error message. Source code: [COCRDLIC.cbl](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/app/cbl/COCRDLIC.cbl).

### Roles and permissions

This use case is available from the regular user menu. No separate role check was found inside the card list program. Source code: [COMEN02Y.cpy](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/app/cpy/COMEN02Y.cpy), [COMEN01C.cbl](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/app/cbl/COMEN01C.cbl), [COCRDLIC.cbl](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/app/cbl/COCRDLIC.cbl).

### Key data involved

This use case reads card records and filters them by account relationship or card number. It passes the selected card and account context to the next screen. Source code: [COCRDLIC.cbl](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/app/cbl/COCRDLIC.cbl), [CVACT02Y.cpy](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/app/cpy/CVACT02Y.cpy), [COCOM01Y.cpy](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/app/cpy/COCOM01Y.cpy).

### Notable constraints

The card list reads card records directly and filters them in the program. No customer data is shown on this screen. Source code: [COCRDLIC.cbl](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/app/cbl/COCRDLIC.cbl).

## Card update

### Description

A regular user can update selected card details. The editable business fields are the embossed cardholder name, active status, and expiration month and year. Source code: [COCRDUPC.cbl](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/app/cbl/COCRDUPC.cbl), [COCRDUP.bms](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/app/bms/COCRDUP.bms), [screens-and-transactions.md](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/docs/screens-and-transactions.md).

The card security code is retained from the existing record and is not edited on this screen. Source code: [COCRDUPC.cbl](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/app/cbl/COCRDUPC.cbl).

### Business rules and logic

Account and card keys must be present, numeric, and nonzero when the user fetches a card directly. Source code: [COCRDUPC.cbl](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/app/cbl/COCRDUPC.cbl).

The embossed name is required and must contain letters and spaces. Source code: [COCRDUPC.cbl](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/app/cbl/COCRDUPC.cbl).

Active status must be answered as yes or no. Source code: [COCRDUPC.cbl](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/app/cbl/COCRDUPC.cbl).

Expiration month must be a valid calendar month. Expiration year must fall within the accepted year range. Source code: [COCRDUPC.cbl](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/app/cbl/COCRDUPC.cbl).

The system compares the edited card to the originally loaded card. If no value changed, the save is blocked with a no-change message. Source code: [COCRDUPC.cbl](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/app/cbl/COCRDUPC.cbl).

The user must confirm the validated change before the system saves it. Source code: [COCRDUPC.cbl](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/app/cbl/COCRDUPC.cbl).

### Roles and permissions

This use case is available from the regular user menu. No separate role check was found inside the card update program. Source code: [COMEN02Y.cpy](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/app/cpy/COMEN02Y.cpy), [COMEN01C.cbl](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/app/cbl/COMEN01C.cbl), [COCRDUPC.cbl](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/app/cbl/COCRDUPC.cbl).

### Key data involved

This use case reads and writes card data. It uses account context during the screen flow. Source code: [COCRDUPC.cbl](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/app/cbl/COCRDUPC.cbl), [CVACT02Y.cpy](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/app/cpy/CVACT02Y.cpy), [COCOM01Y.cpy](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/app/cpy/COCOM01Y.cpy).

### Notable constraints

The save flow locks the card record, rechecks it against the originally displayed values, and rewrites the card only if it has not changed since display. Source code: [COCRDUPC.cbl](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/app/cbl/COCRDUPC.cbl).

I did not find a direct check that the entered account number must match the card’s stored account relationship before rewrite. Source code: [COCRDUPC.cbl](https://github.com/lowtouch-ai/cardcore/blob/krithi/dev/app/cbl/COCRDUPC.cbl).

## Bill payment

### Description

A regular user can pay the current account balance through the bill payment screen. The user enters an account, reviews the current balance, and confirms whether to submit payment.
