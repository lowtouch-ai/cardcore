**Functional Requirements Specification: CardCore Account and Customer Management**

**1. Scope and Runtime Boundary**

CardCore is the legacy AWS CardDemo-derived z/OS source repository for COBOL, CICS, VSAM, JCL, and optional Db2/IMS/MQ modules; it is source-only and has no local build or local runtime. Compilation and execution occur on z/OS or an emulator through JCL and CICS resources. [AGENTS.md](/appz/git/lowtouch-ai/cardcore/AGENTS.md:8) [AGENTS.md](/appz/git/lowtouch-ai/cardcore/AGENTS.md:47)

This FRS covers account and customer management behavior implemented in the legacy source: account inquiry, account/customer update, account balance mutation through bill payment and batch posting, statement reads, optional MQ account inquiry, and optional payment authorization account/customer lookups. Customer/account create and delete are out of scope for current implementation because the base online inventory provides account view/update only, and no base CICS program implements `WRITE` or `DELETE` for `ACCTDAT` or `CUSTDAT`. [docs/screens-and-transactions.md](/appz/git/lowtouch-ai/cardcore/docs/screens-and-transactions.md:142) [docs/screens-and-transactions.md](/appz/git/lowtouch-ai/cardcore/docs/screens-and-transactions.md:155) [app/cbl/COACTUPC.cbl](/appz/git/lowtouch-ai/cardcore/app/cbl/COACTUPC.cbl:4065)

The modern target is not implemented in this repository. The intended migration targets are sibling repositories: `cardcore-api` using Spring Boot 3 / Java 17 with entities mirroring VSAM layouts, and `cardcore-ui` using Next.js 14 / TypeScript / Tailwind, with server-side calls to `cardcore-api`. [AGENTS.md](/appz/git/lowtouch-ai/cardcore/AGENTS.md:32)

**3. Architecture and Component Interactions**

Base online account/customer management is a CICS/BMS/VSAM flow. `CAVW` maps to `COACTVWC` and mapset `COACTVW`; `CAUP` maps to `COACTUPC` and mapset `COACTUP`; both use VSAM files `CXACAIX`, `ACCTDAT`, and `CUSTDAT`, with account lookup resolving through the account alternate index before reading account and customer records. [docs/screens-and-transactions.md](/appz/git/lowtouch-ai/cardcore/docs/screens-and-transactions.md:142) [docs/screens-and-transactions.md](/appz/git/lowtouch-ai/cardcore/docs/screens-and-transactions.md:155) [app/cbl/COACTVWC.cbl](/appz/git/lowtouch-ai/cardcore/app/cbl/COACTVWC.cbl:687) [app/cbl/COACTUPC.cbl](/appz/git/lowtouch-ai/cardcore/app/cbl/COACTUPC.cbl:3608)

CICS resource definitions bind logical file names to datasets: `ACCTDAT` to `AWS.M2.CARDDEMO.ACCTDATA.VSAM.KSDS`, `CUSTDAT` to `AWS.M2.CARDDEMO.CUSTDATA.VSAM.KSDS`, `CCXREF` to the card cross-reference KSDS, and `CXACAIX` to the card cross-reference alternate index path. These file definitions specify `READINTEG(UNCOMMITTED)`, `DSNSHARING(ALLREQS)`, `UPDATEMODEL(LOCKING)`, `ADD(YES)`, `BROWSE(YES)`, `DELETE(YES)`, `READ(YES)`, `UPDATE(YES)`, `JOURNAL(NO)`, and `RECOVERY(NONE)`. [app/csd/CARDDEMO.CSD](/appz/git/lowtouch-ai/cardcore/app/csd/CARDDEMO.CSD:1) [app/csd/CARDDEMO.CSD](/appz/git/lowtouch-ai/cardcore/app/csd/CARDDEMO.CSD:37) [app/csd/CARDDEMO.CSD](/appz/git/lowtouch-ai/cardcore/app/csd/CARDDEMO.CSD:50) [app/csd/CARDDEMO.CSD](/appz/git/lowtouch-ai/cardcore/app/csd/CARDDEMO.CSD:63)

The batch architecture brackets VSAM access with `CLOSEFIL` and `OPENFIL` jobs so scheduled batch jobs can obtain exclusive file access, and uses `WAITSTEP` between phases. Daily posting runs `POSTTRAN`; monthly interest runs `INTCALC`; statement generation runs `CREASTMT`. [docs/batch-jobs.md](/appz/git/lowtouch-ai/cardcore/docs/batch-jobs.md:6)

Optional integrations are separate source trees. `app-vsam-mq` adds MQ-triggered account inquiry using `COACCT01`; `app-authorization-ims-db2-mq` adds real-time authorization over MQ, IMS storage, Db2 fraud persistence, and two-phase commit behavior; `app-transaction-type-db2` adds Db2 transaction-type maintenance and VSAM-compatible extraction. [docs/optional-modules.md](/appz/git/lowtouch-ai/cardcore/docs/optional-modules.md:1) [app/app-vsam-mq/README.md](/appz/git/lowtouch-ai/cardcore/app/app-vsam-mq/README.md:6) [app/app-authorization-ims-db2-mq/README.md](/appz/git/lowtouch-ai/cardcore/app/app-authorization-ims-db2-mq/README.md:36) [app/app-transaction-type-db2/README.md](/appz/git/lowtouch-ai/cardcore/app/app-transaction-type-db2/README.md:8)

**7. Scope Boundary on Create/Delete**

Account create is out of scope. Customer create is out of scope. Account delete is out of scope. Customer delete is out of scope. The base CICS inventory includes account view `CAVW` and account update `CAUP`, but no account/customer create or delete transaction; admin create/delete functions apply to user-security records, not `ACCTDAT` or `CUSTDAT`.
