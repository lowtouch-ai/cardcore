# Functional Specification Document: Account and Customer Management

## Architecture

CardCore is the `lowtouch-ai` fork of AWS CardDemo. The current application is a z/OS source-only system implemented with COBOL, CICS, VSAM, JCL, BMS maps, copybooks, CSD resources, and optional Db2/IMS/MQ modules; it does not compile or run locally, and verification requires upload to a mainframe or emulator. Sources: `AGENTS.md:8-12`, `AGENTS.md:49-79`.

The migration target documented in this repository is split across sibling repositories: `cardcore-api`, a Spring Boot 3 / Java 17 API whose entities mirror VSAM records such as `Customer`, `Account`, `Card`, `CardXref`, and `Transaction`; and `cardcore-ui`, a Next.js 14 / TypeScript / Tailwind application that calls `cardcore-api` server-side. The CardCore legacy repository remains read-only input to the Krithi COBOL-to-Java migration pipeline. Sources: `AGENTS.md:21-45`, `README.md:31-50`, `README.md:86-94`.

The online runtime is CICS transaction-driven. Transactions such as `CAVW`, `CAUP`, `CCLI`, `CCDL`, `CCUP`, `CB00`, `CM00`, and `CA00` route to COBOL programs, render BMS mapsets, exchange state through `CARDDEMO-COMMAREA`, and access VSAM files through CICS `READ`, `READ UPDATE`, `REWRITE`, `STARTBR`, `READNEXT`, and `READPREV`. Relevant CICS file resources are defined with `RECORDFORMAT(V)`, `UPDATEMODEL(LOCKING)`, and `RECOVERY(NONE)`. Sources: `app/csd/CARDDEMO.CSD:1-99`, `app/csd/CARDDEMO.CSD:173-256`, `app/csd/CARDDEMO.CSD:306-448`, `app/cpy/COCOM01Y.cpy:19-44`.

The online access model is menu-routed. `COSGN00C` stores `CDEMO-USER-ID` and `CDEMO-USER-TYPE` in `CARDDEMO-COMMAREA`; `COMEN01C` routes regular-user options to account, card, transaction, report, bill-payment, and optional pending-authorization programs; `COADM01C` routes admin options to internal user-security and optional transaction-type maintenance. The scanned account/card CICS transactions have `RESSEC(NO)` and `CMDSEC(NO)`. Sources: `app/cbl/COSGN00C.cbl:211-257`, `app/cpy/COMEN02Y.cpy:19-99`, `app/cpy/COADM02Y.cpy:19-59`, `app/cbl/COMEN01C.cbl:117-190`, `app/csd/CARDDEMO.CSD:306-448`.

Batch processing is JCL/DD-name driven. Programs bind COBOL `SELECT ... ASSIGN TO` names to JCL DDs and process VSAM or sequential datasets outside the CICS menu model. Daily posting uses `POSTTRAN.jcl`; monthly interest uses `INTCALC.jcl` followed by `COMBTRAN.jcl`; statement generation uses `CREASTMT.JCL`; branch migration uses `CBEXPORT.jcl` and `CBIMPORT.jcl`. Sources: `AGENTS.md:100-108`, `app/jcl/POSTTRAN.jcl:23-42`, `app/jcl/INTCALC.jcl:22-41`, `app/jcl/COMBTRAN.jcl:22-49`, `app/jcl/CREASTMT.JCL:79-96`, `app/jcl/CBIMPORT.jcl:22-60`.

Optional integrations are separate installable modules. `app/app-vsam-mq` adds MQ-driven account/date inquiry through `CDRA` and `CDRD`; `app/app-transaction-type-db2` adds Db2-backed transaction-type maintenance; `app/app-authorization-ims-db2-mq` adds card authorization processing using IMS pending-authorization data, Db2 fraud tables, and MQ queues. Sources: `docs/optional-modules.md:1-11`, `app/app-vsam-mq/README.md:6-35`, `app/app-transaction-type-db2/README.md:6-8`, `app/app-authorization-ims-db2-mq/README.md:6-7`.

## Data Model

### Core VSAM Files

VSAM records are fixed layouts with no native nullability. Blank, zero, and low-value states are handled by COBOL and BMS validation logic rather than schema constraints. Sources: `app/cpy/CVCUS01Y.cpy:1-23`, `app/cpy/CVACT01Y.cpy:1-17`, `app/cbl/COACTUPC.cbl:1856-2221`.

`CUSTOMER-RECORD` maps to `CUSTDAT`, dataset `AWS.M2.CARDDEMO.CUSTDATA.VSAM.KSDS`, record size 500, primary key `CUST-ID` at offset 0 length 9. Fields: `CUST-ID PIC 9(09)`; `CUST-FIRST-NAME`, `CUST-MIDDLE-NAME`, `CUST-LAST-NAME PIC X(25)`; `CUST-ADDR-LINE-1`, `-2`, `-3 PIC X(50)`; `CUST-ADDR-STATE-CD PIC X(02)`; `CUST-ADDR-COUNTRY-CD PIC X(03)`; `CUST-ADDR-ZIP PIC X(10)`; `CUST-PHONE-NUM-1`, `-2 PIC X(15)`; `CUST-SSN PIC 9(09)`; `CUST-GOVT-ISSUED-ID PIC X(20)`; `CUST-DOB-YYYY-MM-DD PIC X(10)`; `CUST-EFT-ACCOUNT-ID PIC X(10)`; `CUST-PRI-CARD-HOLDER-IND PIC X(01)`; `CUST-FICO-CREDIT-SCORE PIC 9(03)`; filler `PIC X(168)`. Sources: `app/cpy/CVCUS01Y.cpy:1-23`, `app/jcl/CUSTFILE.jcl:46-54`, `app/csd/CARDDEMO.CSD:50-62`.

`ACCOUNT-RECORD` maps to `ACCTDAT`, dataset `AWS.M2.CARDDEMO.ACCTDATA.VSAM.KSDS`, record size 300, primary key `ACCT-ID` at offset 0 length 11. Fields: `ACCT-ID PIC 9(11)`; `ACCT-ACTIVE-STATUS PIC X(01)`; `ACCT-CURR-BAL PIC S9(10)V99`; `ACCT-CREDIT-LIMIT PIC S9(10)V99`; `ACCT-CASH-CREDIT-LIMIT PIC S9(10)V99`; `ACCT-OPEN-DATE PIC X(10)`; `ACCT-EXPIRAION-DATE PIC X(10)`; `ACCT-REISSUE-DATE PIC X(10)`; `ACCT-CURR-CYC-CREDIT PIC S9(10)V99`; `ACCT-CURR-CYC-DEBIT PIC S9(10)V99`; `ACCT-ADDR-ZIP PIC X(10)`; `ACCT-GROUP-ID PIC X(10)`; filler `PIC X(178)`. Sources: `app/cpy/CVACT01Y.cpy:1-17`, `app/jcl/ACCTFILE.jcl:36-44`, `app/csd/CARDDEMO.CSD:1-12`.

`CARD-RECORD` maps to `CARDDAT`, dataset `AWS.M2.CARDDEMO.CARDDATA.VSAM.KSDS`, record size 150, primary key `CARD-NUM` at offset 0 length 16, alternate index path `CARDAIX` keyed by `CARD-ACCT-ID` at offset 16 length 11. Fields: `CARD-NUM PIC X(16)`; `CARD-ACCT-ID PIC 9(11)`; `CARD-CVV-CD PIC 9(03)`; `CARD-EMBOSSED-NAME PIC X(50)`; `CARD-EXPIRAION-DATE PIC X(10)`; `CARD-ACTIVE-STATUS PIC X(01)`; filler `PIC X(59)`. Sources: `app/cpy/CVACT02Y.cpy:1-11`, `app/jcl/CARDFILE.jcl:50-58`, `app/jcl/CARDFILE.jcl:83-102`, `app/csd/CARDDEMO.CSD:13-36`.

`CARD-XREF-RECORD` maps to `CCXREF`, dataset `AWS.M2.CARDDEMO.CARDXREF.VSAM.KSDS`, record size 50, primary key `XREF-CARD-NUM` at offset 0 length 16, alternate index path `CXACAIX` keyed by `XREF-ACCT-ID` at offset 25 length 11. Fields: `XREF-CARD-NUM PIC X(16)`; `XREF-CUST-ID PIC 9(09)`; `XREF-ACCT-ID PIC 9(11)`; filler `PIC X(14)`. Sources: `app/cpy/CVACT03Y.cpy:1-8`, `app/jcl/XREFFILE.jcl:39-47`, `app/jcl/XREFFILE.jcl:72-92`, `app/csd/CARDDEMO.CSD:37-75`.

`TRAN-RECORD` maps to `TRANSACT`, dataset `AWS.M2.CARDDEMO.TRANSACT.VSAM.KSDS`, record size 350, primary key `TRAN-ID` at offset 0 length 16, alternate index path keyed by `TRAN-ORIG-TS` at offset 304 length 26. Fields: `TRAN-ID PIC X(16)`; `TRAN-TYPE-CD PIC X(02)`; `TRAN-CAT-CD PIC 9(04)`; `TRAN-SOURCE PIC X(10)`; `TRAN-DESC PIC X(100)`; `TRAN-AMT PIC S9(09)V99`; `TRAN-MERCHANT-ID PIC 9(09)`; `TRAN-MERCHANT-NAME PIC X(50)`; `TRAN-MERCHANT-CITY PIC X(50)`; `TRAN-MERCHANT-ZIP PIC X(10)`; `TRAN-CARD-NUM PIC X(16)`; `TRAN-ORIG-TS PIC X(26)`; `TRAN-PROC-TS PIC X(26)`; filler `PIC X(20)`. Sources: `app/cpy/CVTRA05Y.cpy:1-18`, `app/jcl/TRANFILE.jcl:49-57`, `app/jcl/TRANFILE.jcl:82-101`, `app/csd/CARDDEMO.CSD:76-87`.

`DALYTRAN-RECORD` is the daily transaction input layout, 350 bytes, with the same field shapes as `TRAN-RECORD` prefixed `DALYTRAN-*`. Sources: `app/cpy/CVTRA06Y.cpy:1-18`, `app/jcl/POSTTRAN.jcl:23-42`.

`TRAN-CAT-BAL-RECORD` maps to `TCATBALF`, record size 50, key length 17 composed of `TRANCAT-ACCT-ID PIC 9(11)`, `TRANCAT-TYPE-CD PIC X(02)`, and `TRANCAT-CD PIC 9(04)`. It stores `TRAN-CAT-BAL PIC S9(09)V99` plus filler `PIC X(22)`. Sources: `app/cpy/CVTRA01Y.cpy:1-10`, `app/jcl/TCATBALF.jcl:36-44`.

`DIS-GROUP-RECORD` maps to `DISCGRP`, record size 50, key length 16 composed of `DIS-ACCT-GROUP-ID PIC X(10)`, `DIS-TRAN-TYPE-CD PIC X(02)`, and `DIS-TRAN-CAT-CD PIC 9(04)`. It stores `DIS-INT-RATE PIC S9(04)V99` plus filler `PIC X(28)`. Sources: `app/cpy/CVTRA02Y.cpy:1-10`, `app/jcl/DISCGRP.jcl:36-44`.

`TRAN-TYPE-RECORD` maps to a 60-byte transaction-type VSAM file keyed by `TRAN-TYPE PIC X(02)` and stores `TRAN-TYPE-DESC PIC X(50)` plus filler `PIC X(08)`. `TRAN-CAT-RECORD` maps to a 60-byte category file keyed by `TRAN-TYPE-CD PIC X(02)` plus `TRAN-CAT-CD PIC 9(04)` and stores `TRAN-CAT-TYPE-DESC PIC X(50)` plus filler `PIC X(04)`. Sources: `app/cpy/CVTRA03Y.cpy:1-7`, `app/cpy/CVTRA04Y.cpy:1-9`, `app/jcl/TRANTYPE.jcl:36-44`, `app/jcl/TRANCATG.jcl:36-44`.

`SEC-USER-DATA` maps to `USRSEC`, dataset `AWS.M2.CARDDEMO.USRSEC.VSAM.KSDS`, record size 80, key `SEC-USR-ID` at offset 0 length 8. Fields: `SEC-USR-ID PIC X(08)`; `SEC-USR-FNAME PIC X(20)`; `SEC-USR-LNAME PIC X(20)`; `SEC-USR-PWD PIC X(08)`; `SEC-USR-TYPE PIC X(01)`; `SEC-USR-FILLER PIC X(23)`. Sources: `app/cpy/CSUSR01Y.cpy:17-23`, `app/jcl/DUSRSECJ.jcl:64-68`, `app/csd/CARDDEMO.CSD:88-99`.

`CARDDEMO-COMMAREA` is the CICS session/request context: `CDEMO-FROM-TRANID PIC X(04)`, `CDEMO-FROM-PROGRAM PIC X(08)`, `CDEMO-TO-TRANID PIC X(04)`, `CDEMO-TO-PROGRAM PIC X(08)`, `CDEMO-USER-ID PIC X(08)`, `CDEMO-USER-TYPE PIC X(01)` with 88 values `ADMIN='A'` and `USER='U'`, `CDEMO-PGM-CONTEXT PIC 9(01)` with 88 values `ENTER=0` and `REENTER=1`, `CDEMO-CUST-ID PIC 9(09)`, customer names `PIC X(25)`, `CDEMO-ACCT-ID PIC 9(11)`, `CDEMO-ACCT-STATUS PIC X(01)`, `CDEMO-CARD-NUM PIC 9(16)`, and last map/mapset names `PIC X(7)`. Sources: `app/cpy/COCOM01Y.cpy:19-44`.

`EXPORT-RECORD` is a 500-byte migration envelope keyed in `CBEXPORT.jcl` by offset 28 length 4. Envelope fields are `EXPORT-REC-TYPE PIC X(1)`, `EXPORT-TIMESTAMP PIC X(26)`, `EXPORT-SEQUENCE-NUM PIC 9(9) COMP`, `EXPORT-BRANCH-ID PIC X(4)`, `EXPORT-REGION-CODE PIC X(5)`, and `EXPORT-RECORD-DATA PIC X(460)`. Redefines provide customer, account, transaction, xref, and card payload layouts, including packed/binary variants such as `EXP-CUST-ID PIC 9(09) COMP`, `EXP-CUST-FICO-SCORE PIC 9(03) COMP-3`, `EXP-ACCT-CURR-BAL PIC S9(10)V99 COMP-3`, `EXP-TRAN-AMT PIC S9(09)V99 COMP-3`, and `EXP-CARD-CVV-CD PIC 9(03) COMP`. Sources: `app/cpy/CVEXPORT.cpy:1-100`, `app/jcl/CBEXPORT.jcl:30-38`.

### Optional Relational, IMS, and MQ Schemas

The optional transaction-type Db2 module defines `CARDDEMO.TRANSACTION_TYPE(TR_TYPE CHAR(2) NOT NULL PRIMARY KEY, TR_DESCRIPTION VARCHAR(50) NOT NULL)` and a unique index on `TR_TYPE`. Sources: `app/app-transaction-type-db2/ddl/TRNTYPE.ddl:1-4`, `app/app-transaction-type-db2/ddl/XTRNTYPE.ddl:1-5`, `app/app-transaction-type-db2/ddl/TRNTYCAT.ddl:1-7`, `app/app-transaction-type-db2/ddl/XTRNTYCAT.ddl:1-5`.

The optional authorization Db2 table is `CARDDEMO.AUTHFRDS` with primary key `(CARD_NUM, AUTH_TS)`. Columns: `CARD_NUM CHAR(16) NOT NULL`, `AUTH_TS TIMESTAMP NOT NULL`, `AUTH_TYPE CHAR(4)`, `CARD_EXPIRY_DATE CHAR(4)`, `MESSAGE_TYPE CHAR(6)`, `MESSAGE_SOURCE CHAR(6)`, `AUTH_ID_CODE CHAR(6)`, `AUTH_RESP_CODE CHAR(2)`, `AUTH_RESP_REASON CHAR(4)`, `PROCESSING_CODE CHAR(6)`, `TRANSACTION_AMT DECIMAL(12,2)`, `APPROVED_AMT DECIMAL(12,2)`, `MERCHANT_CATAGORY_CODE CHAR(4)`, `ACQR_COUNTRY_CODE CHAR(3)`, `POS_ENTRY_MODE SMALLINT`, `MERCHANT_ID CHAR(15)`, `MERCHANT_NAME VARCHAR(22)`, `MERCHANT_CITY CHAR(13)`, `MERCHANT_STATE CHAR(02)`, `MERCHANT_ZIP CHAR(09)`, `TRANSACTION_ID CHAR(15)`, `MATCH_STATUS CHAR(1)`, `AUTH_FRAUD CHAR(1)`, `FRAUD_RPT_DATE DATE`, `ACCT_ID DECIMAL(11)`, and `CUST_ID DECIMAL(9)`. A unique index orders `(CARD_NUM ASC, AUTH_TS DESC)`. Sources: `app/app-authorization-ims-db2-mq/ddl/AUTHFRDS.ddl:1-28`, `app/app-authorization-ims-db2-mq/ddl/XAUTHFRD.ddl:1-4`.

The optional authorization IMS database `DBPAUTP0` is HIDAM/VSAM with root segment `PAUTSUM0 BYTES=100`, root key field `ACCNTID START=1 BYTES=6 TYPE=P`, logical child `PAUTINDX`, and child segment `PAUTDTL1 BYTES=200` with field `PAUT9CTS START=1 BYTES=8 TYPE=C`. The secondary index database `DBPAUTX0` uses segment `PAUTINDX BYTES=6` with `INDXSEQ START=1 BYTES=6 TYPE=P`. Sources: `app/app-authorization-ims-db2-mq/ims/DBPAUTP0.dbd:18-37`, `app/app-authorization-ims-db2-mq/ims/DBPAUTX0.dbd:18-31`.

Detail copybook `CIPAUDTY` stores authorization timestamp keys, card number, auth type, expiry, response fields, processing code, transaction/approved amounts, merchant data, transaction ID, match/fraud indicators, report date, and filler. Sources: `app/app-authorization-ims-db2-mq/cpy/CIPAUSMY.cpy:19-31`, `app/app-authorization-ims-db2-mq/cpy/CIPAUDTY.cpy:19-54`.

The optional VSAM/MQ module defines MQ requests with `REQUEST-TYPE PIC X(4)`, `REQUEST-ID PIC X(8)`, and either no payload for date or `ACCOUNT-NUMBER PIC X(11)` for account inquiry. Account responses use `RESPONSE-TYPE PIC X(4)`, `RESPONSE-ID PIC X(8)`, and `ACCOUNT-DATA PIC X(300)`. `COACCT01` internally consumes a 1000-byte request buffer redefined as `WS-FUNC PIC X(04)`, `WS-KEY PIC 9(11)`, filler, and emits account fields from `ACCOUNT-RECORD`. ## Use case: sign on and route to account/customer functions

Implementation identifiers: CICS transaction `CC00` routes to `COSGN00C`; mapset `COSGN00` provides input fields `USERIDI PIC X(8)` and `PASSWDI PIC X(8)` plus `ERRMSGI PIC X(78)`. Sources: `app/csd/CARDDEMO.CSD:249-256`, `app/csd/CARDDEMO.CSD:378-387`, `app/cpy-bms/COSGN00.CPY:60-84`.

`COSGN00C` receives the map, requires both user ID and password, uppercases both values, reads `USRSEC` by `WS-USER-ID`, compares `SEC-USR-PWD` to the supplied password, and rejects not-found, password mismatch, and non-normal file responses through separate branches. Sources: `app/cbl/COSGN00C.cbl:108-140`, `app/cbl/COSGN00C.cbl:211-257`.

On successful authentication, `COSGN00C` moves `SEC-USR-ID` and `SEC-USR-TYPE` into `CDEMO-USER-ID` and `CDEMO-USER-TYPE`. `SEC-USR-TYPE='A'` routes to admin program `COADM01C`; all other successful users route to regular menu program `COMEN01C`. Sources: `app/cbl/COSGN00C.cbl:221-240`, `app/cpy/COCOM01Y.cpy:19-31`.

`COMEN01C` validates menu input as numeric and in range, blocks regular users from admin-only entries, checks optional `COPAUS0C` installation with `EXEC CICS INQUIRE PROGRAM`, and transfers control to the selected program with `CARDDEMO-COMMAREA`. Regular-user account/customer-relevant options are account view, account update, card list, card view, card update, bill payment, and optional pending authorization. Sources: `app/cbl/COMEN01C.cbl:117-190`, `app/cpy/COMEN02Y.cpy:19-99`.

## Use case: view account and customer details

Implementation identifiers: CICS transaction `CAVW`, program `COACTVWC`, mapset `COACTVW`, account search field `ACCTSIDI PIC 99999999999`, account output fields for status, dates, balances, cycle totals, ZIP, group, and customer output fields for ID, SSN, DOB, FICO, name, address, phones, government ID, EFT account, and primary-card indicator. Sources: `app/csd/CARDDEMO.CSD:181-188`, `app/csd/CARDDEMO.CSD:317-326`, `app/cpy-bms/COACTVW.CPY:55-240`.

Input normalization replaces `*` and spaces with low values before validation. The account number is required, must be numeric, must be nonzero, and must occupy the 11-digit account field; invalid input returns `Account Filter must be a non-zero 11 digit number`. Sources: `app/cbl/COACTVWC.cbl:622-680`.

Lookup order is `CCXREF` alternate path `CXACAIX` by `XREF-ACCT-ID`, then `ACCTDAT` by `ACCT-ID`, then `CUSTDAT` by `CUST-ID`. The xref read populates customer ID and card number used by later display logic. Source-specific not-found and file-error branches distinguish missing account relationship, missing account master, missing customer master, and generic file errors. Sources: `app/cbl/COACTVWC.cbl:687-715`, `app/cbl/COACTVWC.cbl:723-868`.

Display formatting moves account fields directly from `ACCOUNT-RECORD`, formats SSN as `999-99-9999`, and moves customer fields from `CUSTOMER-RECORD`. Sources: `app/cbl/COACTVWC.cbl:460-522`.

## Use case: update account and customer details

Implementation identifiers: CICS transaction `CAUP`, program `COACTUPC`, mapset `COACTUP`. The screen receives `ACCTSIDI X(11)`, account status `X(1)`, open/expiry/reissue date components, monetary account fields `X(15)`, group `X(10)`, cycle fields `X(15)`, customer ID `X(9)`, SSN parts `X(3)/X(2)/X(4)`, DOB components, FICO `X(3)`, names `X(25)`, address fields, ZIP `X(5)`, phones split into area/prefix/line, government ID `X(20)`, EFT `X(10)`, and primary-card flag `X(1)`. Sources: `app/csd/CARDDEMO.CSD:173-180`, `app/csd/CARDDEMO.CSD:306-316`, `app/cpy-bms/COACTUP.CPY:55-330`.

Before details are fetched, account search input is required, numeric, nonzero, and 11 digits; the invalid-search message is `Account Number if supplied must be a 11 digit Non-Zero Number`. Sources: `app/cbl/COACTUPC.cbl:1429-1468`, `app/cbl/COACTUPC.cbl:1783-1817`.

When details are shown, `COACTUPC` validates account status and primary-card indicator through `1220-EDIT-YESNO`, requiring `Y` or `N`. Signed monetary fields are required and validated with `FUNCTION TEST-NUMVAL-C`. Dates use `CSUTLDPY`, which requires numeric year/month/day, century `19` or `20`, and CEEDAYS calendar validity; DOB also cannot be a future date. Sources: `app/cbl/COACTUPC.cbl:1472-1507`, `app/cbl/COACTUPC.cbl:1856-1894`, `app/cbl/COACTUPC.cbl:2180-2221`, `app/cpy/CSUTLDPY.cpy:18-80`, `app/cpy/CSUTLDPY.cpy:300-370`.

Name and alphabetic fields allow only alphabetic characters and spaces; alphanumeric fields allow letters, numbers, and spaces. Phone numbers are optional only when the whole phone is blank; otherwise area code, prefix, and line number are required, numeric, and nonzero, with area code checked against the North America general-purpose code table. SSN requires numeric nonzero parts and rejects first three digits `000`, `666`, and `900` through `999`. State code and state/ZIP prefix combinations are table validated. FICO must be between 300 and 850. Sources: `app/cbl/COACTUPC.cbl:1898-2107`, `app/cbl/COACTUPC.cbl:2225-2428`, `app/cbl/COACTUPC.cbl:2431-2488`, `app/cbl/COACTUPC.cbl:2493-2558`, `app/cpy/CSLKPCDY.cpy:521-560`, `app/cpy/CSLKPCDY.cpy:1012-1100`.

The fetch path reads the account relationship, account master, and customer master, then stores original account/customer values in `ACUP-OLD-*` work fields. No-change detection compares old and new values, uppercasing/trimming string fields, and reports no changes without rewriting. Sources: `app/cbl/COACTUPC.cbl:1681-1777`, `app/cbl/COACTUPC.cbl:3608-3883`.

Save requires PF5 after validation has set the change set to `ACUP-CHANGES-OK-NOT-CONFIRMED`. The save path locks account and customer with `READ UPDATE`, compares the locked records against the original screen snapshot, builds updated `ACCOUNT-RECORD` and `CUSTOMER-RECORD`, rewrites account first, rewrites customer second, and attempts account rollback if customer rewrite fails. Sources: `app/cbl/COACTUPC.cbl:2562-2643`, `app/cbl/COACTUPC.cbl:3888-4102`, `app/cbl/COACTUPC.cbl:4109-4193`.

## Use case: list and select cards by account or card number

Implementation identifiers: CICS transaction `CCLI`, program `COCRDLIC`, mapset `COCRDLI`. The list screen has page number `PAGENOI X(3)`, optional filters `ACCTSIDI X(11)` and `CARDSIDI X(16)`, and seven row slots with select/action, account number, card number, and status fields. Selection handling permits only one selected row and validates the action as view/select or update. ## Use case: post daily transactions to accounts

## Use case: pay account balance online

## Non-functional and Operational Constraints

Account/customer update and card update use optimistic conflict detection: initial record values are retained in working storage, records are re-read with update locks before save, current locked values are compared to the original displayed values, and rewrite is rejected if another update changed the record. Sources: `app/cbl/COACTUPC.cbl:3888-4193`, `app/cbl/COCRDUPC.cbl:1420-1519`.

CICS file resources for core account/customer/card/transaction/user-security files specify `RECOVERY(NONE)`. The application compensates locally in the account/customer update path by attempting account rollback when customer rewrite fails, but the CSD does not define file-level recovery. Sources: `app/csd/CARDDEMO.CSD:1-99`, `app/cbl/COACTUPC.cbl:4065-4102`.

Sensitive fields are stored and displayed in clear application fields: SSN, government-issued ID, EFT account ID, FICO score, internal password, account balances, credit limits, and card security code. No masking/audit rule is defined in the scanned source beyond display formatting for SSN in account view. Sources: `app/cpy/CVCUS01Y.cpy:4-23`, `app/cpy/CVACT02Y.cpy:4-11`, `app/cpy/CSUSR01Y.cpy:17-23`, `app/cbl/COACTVWC.cbl:493-522`.

The target Postgres DDL for `cardcore-api` is not present in this repository. The repository states that migrated entities mirror the legacy VSAM layouts and that `docs/data-model.md` is the cross-reference; exact JPA annotations, indexes, API endpoints, and UI route contracts must be read from the sibling repositories when available. Sources: `AGENTS.md:21-45`, `README.md:31-50`.
